\section{Related Work}

\textbf{Secure program synthesis and specification elicitation.}
SPS requires synthesizing software, specifications, and proofs together
\cite{VonHippel2026SPS}. Dodds argues that complete formal specifications are
often unavailable or incoherent in real systems, while informal specifications
remain practically useful communication tools \cite{Dodds2025Specs}.
SpecOracle sits in this gap: it treats informal engineering principles as
prompt-level structural oracles rather than attempting to formalize taste.

\textbf{Executable oracles and degrees of freedom.}
Regehr argues that coding agents fail when given freedom to do poor work and
that executable oracles can pinch outputs toward correctness
\cite{Regehr2026ZeroDOF}. SpecOracle tests a weaker intervention: whether a
non-executable informal spec still collapses structural degrees of freedom.
The positive CC result and null context-ablation result should both be read
against this framing.

\textbf{Spec-conditioned decoding.}
Approximately Aligned Decoding constrains LLM outputs at decode time while
managing distribution distortion and computational efficiency
\cite{Melcer2024AprAD}. SpecOracle differs by using in-context conditioning
only: no custom decoder, no formal constraint checker, and structural metrics
rather than hard constraint satisfaction as the primary outcome.

\textbf{Evaluation methods.}
Functional correctness follows the code-generation tradition of HumanEval and
Pass@k estimation \cite{Chen2021HumanEval}. Qualitative structure is assessed
with an LLM-as-a-Judge protocol inspired by MT-Bench and Chatbot Arena
\cite{Zheng2023Judge}. Statistical comparison uses the paired Wilcoxon
signed-rank test \cite{Wilcoxon1945}. Static metrics use Radon and Python AST
analysis \cite{Radon, Peters2004Zen}.

\section{Methods}

\textbf{Dataset.}
SlopBench-Min contains 20 Python tasks across JSON handling, state machines,
concurrency, configuration parsing, CLI validation, retry schedules, and data
pipelines. Each task includes functional tests, Day 2 tests, a human reference,
mock fixtures, and declared Day 2 stressors. The stressor taxonomy is
pre-registered in \texttt{data/DESIGN\_NOTES.md}.

\textbf{Generation modes.}
The baseline condition receives only the functional prompt. The oracle
condition receives the same prompt plus the Zen of Python or a task-specific
\texttt{custom\_spec\_override}. The neutral-style ablation says only to write
clean, maintainable Python.

\textbf{Evaluation pipeline.}
Generated modules are executed as untrusted code in a Docker sandbox with
network disabled and resource limits. Static analysis reports cyclomatic
complexity, maintainability index, nesting depth, and function count. A judge
model scores adherence to the active informal spec. SpecArena then asks a
maintenance model to implement a Day 2 feature and repeats the task with the
existing solution replaced by a stub for context ablation.

\textbf{Primary run command.}
\begin{verbatim}
specoracle run --dataset data/slopbench_min \
  --out runs/claude_replicated \
  --provider anthropic --model claude-sonnet-4-6 \
  --judge-provider anthropic --judge-model claude-sonnet-4-6 \
  --modes baseline oracle --samples 3 \
  --temperature 0.8 --require-temperature
\end{verbatim}

\textbf{Maintenance and context-ablation command.}
\begin{verbatim}
specoracle stress --run-dir runs/claude_replicated \
  --provider anthropic --model claude-sonnet-4-6 \
  --temperature 0.8 --require-temperature --context-ablation
\end{verbatim}

\section{Results}

The headline structural result is positive: oracle conditioning lowers mean
cyclomatic complexity from 8.101 to 4.887, with paired Wilcoxon p=0.004. The
Day 2 hard subset also shows a reduction, p=0.023. Functional correctness is
near-complete but not identical: baseline pytest pass rate is 100.0\%, oracle
pytest pass rate is 95.0\%.
